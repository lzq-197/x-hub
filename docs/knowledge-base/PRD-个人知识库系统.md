# PRD：x-hub 个人知识库系统（本地 AI 知识库 + RAG 问答）

- 文档版本：v1.0
- 日期：2026-09-22
- 基础项目：x-hub v0.6.5（Tauri 2 + Vue 3 + TypeScript + Rust，本地优先桌面效率工作台）
- 关联文档：`docs/knowledge-base/开发文档-技术设计.md`

---

## 1. 产品背景与目标

### 1.1 背景

x-hub 是本地优先的个人效率工作台，已具备「速记（Markdown 笔记 + 标签 + 搜索）」「AI 对话（OpenAI 兼容流式）」「全局搜索」等能力。但现有笔记仅有扁平标签体系，无法承载有结构的个人知识库；AI 对话也只会"空答"，无法基于用户自己的知识沉淀给出有依据的回答。

### 1.2 目标

在 x-hub 内构建一个**本地优先的个人知识库系统**：

1. **结构化组织**：为笔记引入**多级文件夹分类 / 目录树**，替代单一扁平列表；
2. **批量导入**：支持从本地 **Markdown 文件/文件夹批量导入**为笔记，自动还原目录结构；
3. **AI 知识问答（RAG）**：笔记向量化后，提问时检索相关片段喂给 AI，AI **结合本地知识库作答并给出引用来源**（来源可点击直达对应笔记）；
4. **知识库统计视图**：**知识地图**（按文件夹统计笔记分布）+ **标签云**（按标签统计使用强度）。

### 1.3 非目标（范围外）

- 不做云端同步 / 多端协作（延续项目"数据不上云"原则）；
- 不做企业级权限、多用户；
- 不做自动爬取网页收藏；
- 不做对话历史与知识库问答的合并（知识库问答为独立入口，可复用 AI 供应商配置）。

## 2. 目标用户与典型场景

**目标用户**：Windows 桌面端的个人知识工作者（与 x-hub 现有用户一致），日常积累工作笔记、读书笔记、技术文档、个人资料。

**典型场景**：

| 场景 | 用户行为 | 期望结果 |
|---|---|---|
| 建立结构 | 把零散速记按「工作 / 学习 / 生活」等目录归档 | 侧栏出现文件夹树，笔记归类清晰，可多级嵌套 |
| 迁移资料 | 把本地已有的 Markdown 资料文件夹（如 Obsidian 笔记库）一次性导入 | 目录结构还原为文件夹树，内容全部可检索 |
| 提问查知识 | 问"我之前记录过关于 XX 的结论是什么" | AI 检索本地笔记，给出答案，并标注引用来源，点击直达原文 |
| 盘点知识 | 查看知识库概况 | 知识地图展示各分类笔记分布，标签云展示热点主题 |

## 3. 功能需求

### 3.1 笔记多级文件夹分类（P0）

- **F1.1 文件夹树**：速记视图左侧展示多级文件夹树（"全部笔记"根节点 + 各级文件夹），支持无限层级（实际限制 ≤ 8 层防递归异常）。
- **F1.2 文件夹 CRUD**：新建（可指定父级）、重命名、删除、移动（拖拽或右键菜单）。
  - 删除策略：**级联删除子树**（含子文件夹与其中笔记，需二次确认）或 **移至其他文件夹**（删除时选择迁移目标，笔记保留）。
  - 移动校验：禁止移动到自身或自己的子孙节点（防环）。
- **F1.3 笔记归档**：笔记可移动/指定到某个文件夹；未归档笔记属于「未分类」，默认展示在"全部笔记"。
- **F1.4 数据兼容**：存量笔记（无 folder_id）全部归入「未分类」，升级后不丢数据、不弹迁移向导。

### 3.2 Markdown 批量导入（P0）

- **F2.1 入口**：速记视图头部「导入」按钮 → 系统目录选择器（选择文件夹，也可选单个 .md 文件）。
- **F2.2 递归导入**：递归扫描所选目录下所有 `.md` / `.markdown` 文件：
  - 文件相对路径的目录层级 → 自动创建（或复用同名）文件夹树；
  - 文件名（去扩展名）→ 笔记标题；文件内容 → 笔记正文；
  - 无扩展名/未知格式文件跳过，记录 skipped。
- **F2.3 去重策略**：以「相对路径 + 文件名」为导入键；已导入过的文件再次导入时**覆盖更新内容与标题**（保持 folder 不动），并给出统计：`imported / updated / skipped / failed`。
- **F2.4 导入完成后**：自动触发新笔记的向量索引（见 3.3）；前端刷新文件夹树与列表，Toast 展示统计结果。
- **F2.5 大目录约束**：单次导入文件数上限 2000（超过截断并提示）；单文件 > 2MB 跳过（记录 failed）。

### 3.3 知识库向量索引（P0）

- **F3.1 分块**：每篇笔记按 Markdown 结构（标题层级 + 段落）切分为知识片段（chunk），片段携带「所属标题链」（如 `# 项目笔记 → ## 架构设计`），便于溯源。
- **F3.2 嵌入**：调用本地 **Ollama**（OpenAI 兼容 `/v1/embeddings`）的 **bge-m3** 模型做向量化（默认 `http://127.0.0.1:11434/v1`）；配置项可改为任意 OpenAI 兼容 embeddings API（如 OpenAI / 硅基流动 / 智谱），支持远程时填写 API Key。
- **F3.3 索引触发**：
  - 手动：知识库视图「重建索引」按钮（全量重建）；
  - 增量：笔记新建/编辑保存后自动增量索引该篇（防抖，保存后 2s 内触发）；
  - 导入完成后自动索引新增/更新的笔记。
- **F3.4 索引状态**：知识库视图展示：已索引笔记数、片段总数、嵌入模型、最近索引时间、索引中状态与进度（百分比）。索引失败（如 Ollama 未启动）给出明确错误提示与重试入口，不影响其余功能。

### 3.4 AI 知识问答（RAG）（P0）

- **F4.1 入口**：侧栏「知识库」视图（独立视图），含问答区 + 索引状态区 + 知识地图/标签云区。
- **F4.2 提问流程**：输入问题 → 后端混合检索（向量相似度为主 + 关键词命中加分）取 Top-K（默认 6，可调 3–10）知识片段 → 与问题一起注入提示词 → 调用 LLM 流式回答。
- **F4.3 模型选择**：问答使用的 LLM 复用 x-hub 现有「AI 助手」供应商模型配置（`设置 → AI助手` 中已配置的模型下拉选择），默认取第一个；平台额度条目（`x-hub 平台`）同样可选。
- **F4.4 引用溯源（核心验收点）**：
  - 提示词强制要求 AI 在答案中用 `[1]` `[2]` 等编号标注引用（编号对应检索片段）；
  - 回答完成后，答案下方渲染**来源卡片列表**：来源笔记标题、所属文件夹路径、命中片段摘要（截断显示）；
  - 点击来源卡片 → 跳转到该笔记（定位到速记视图并打开该笔记），点击「定位片段」可滚动高亮到对应 chunk 内容附近（按标题链 + 片段文本匹配定位）。
- **F4.5 无命中兜底**：检索不到相关片段时，明确告知"知识库中未找到相关内容"，仍可让 AI 基于通用知识回答（提示词注明"以下回答未基于你的知识库"），避免误导。
- **F4.6 会话形态**：问答为**单轮问答**（每次提问独立检索），不做多轮记忆（v1 简化；每轮对话展示最近几条历史可后续增强）。

### 3.5 知识库统计视图：知识地图 + 标签云（P1）

- **F5.1 知识地图**：以文件夹树形态展示各文件夹（含子级）的笔记数量徽标，直观呈现知识分布；点击节点可跳转到速记视图对应文件夹。
- **F5.2 标签云**：以字号/颜色深浅表示标签使用强度（笔记数量），悬停显示数量；点击标签跳转到速记视图并应用该标签筛选。
- **F5.3 总览数字**：知识库视图顶部展示：笔记总数、文件夹数、标签数、知识片段总数。

### 3.6 设置项（P1）

- **F6.1 嵌入配置**（设置 → AI助手 或知识库视图内设置弹窗）：
  - 嵌入服务地址（默认 `http://127.0.0.1:11434/v1`）；
  - 嵌入模型名（默认 `bge-m3`）；
  - API Key（可选，远程服务时填写；本地 Ollama 留空）；Key 存系统钥匙串，界面脱敏（沿用 AI 对话 Key 的交互模式）；
  - 「测试连接」按钮：调用 `/v1/models` 或一次最小嵌入验证连通性，展示成功/失败原因。
- **F6.2 Top-K 默认值（高级）**：检索片段数默认 6，范围 3–10。

## 4. 非功能需求

| 类别 | 要求 |
|---|---|
| 本地优先 | 所有数据（笔记、片段、向量、配置）仅存本机；向量/嵌入默认走本地 Ollama，无任何云上传；远程嵌入/LLM 仅当用户主动配置 API Key 时发生 |
| 性能 | 单篇 ≤ 200KB 笔记索引 < 3s（本地 Ollama）；问答首字延迟 < 2s（复用现有 SSE 流式）；混合检索 < 500ms（万级片段内） |
| 并发 | 索引任务与问答请求互不阻塞主线程（Rust 侧 async/tokio）；索引期间 UI 不卡顿 |
| 健壮性 | Ollama 未启动 / 嵌入失败 → 明确报错、索引状态标记失败、可重试，不影响速记等既有功能 |
| 安全 | API Key 存系统钥匙串（keyring），不明文落盘、界面脱敏；导入文件仅读取用户指定目录 |
| 兼容 | 存量用户数据零迁移成本（新表可空、旧字段可空）；与全局搜索、标签筛选、备份/恢复兼容 |
| 可访问性 | 键盘可操作文件夹树与问答区；引用来源卡片可聚焦；符合项目 WCAG 2.1 AA 基线 |

## 5. 验收标准（产品视角）

1. **文件夹**：可创建多级文件夹、移动笔记、级联删除（二次确认）、禁止移动形成环；存量笔记显示为「未分类」且可正常使用。
2. **导入**：选择一个含 100+ .md 文件的目录导入，目录树完整还原、统计正确（imported/updated/skipped/failed 与实际情况一致）、重复导入会更新内容且不产生重复笔记。
3. **索引**：导入/编辑后自动增量索引；知识库视图状态区数据实时准确；Ollama 关闭时重建索引给出明确错误与重试入口。
4. **问答（核心）**：针对知识库内明确存在的知识提问，AI 回答内容与知识片段一致，答案中标注 `[n]` 引用；来源卡片列出对应笔记；点击来源卡片能打开并定位到该笔记；无相关片段时明确提示未检索到相关内容。
5. **统计**：知识地图各节点数量与实际一致；标签云大小与标签使用量一致；总览数字准确。
6. **回归**：全局搜索、速记增删改、AI 对话、备份/恢复等既有功能不受影响。

## 7. 关键决策记录

| 决策 | 结论 | 理由 |
|---|---|---|
| 知识库文档源 | 统一为 `notes` 表（速记 + 导入文件都是笔记），`kb_chunks` 引用 `note_id` | 单一数据源，全局搜索/标签/文件夹全部打通；避免双份文档体系 |
| 向量存储 | SQLite 新表存 BLOB（f32 小端），运行时暴力余弦 + 关键词加分混合检索 | 个人知识库规模（≤ 10 万片段）下毫秒级；零新增原生依赖，构建稳定 |
| 嵌入模型 | Ollama `bge-m3`（本地免费，中文效果好）；接口用 OpenAI 兼容协议 | 用户已下载 Ollama 模型库；兼容任意 embeddings API |
| 引用机制 | 检索片段编号注入提示词 + 答案 `[n]` 标注 + 结构化 citations 返回 | 可实现性强、可验证 |
| 问答形态 | v1 为单轮问答（每次独立检索） | 简化实现，聚焦核心价值；多轮记忆留待 v2 |
