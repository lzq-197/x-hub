# 设计：知识库问答 UI 打磨（来源分组 + 引用跳转 + 澄清条）

- 日期：2026-09-27
- 状态：对话已确认（方案 1：前端打磨为主）
- 关联：
  - `docs/superpowers/specs/2026-09-25-kb-rag-mvp-design.md`
  - `docs/knowledge-base/PRD-个人知识库系统.md`（F4.4 引用溯源）
  - `src/components/KnowledgeView.vue`、`src-tauri/src/knowledge.rs`（`build_rag_system_prompt`）

## 1. 目标与范围

改善问答完成后的观感与溯源效率：来源列表按笔记合并、片段摘要默认收起；答案 Markdown 更清晰；正文 `[n]` 可点跳到来源并高亮；疑似笔误用「澄清条」展示（模型优先 + 启发式兜底）。

### 1.1 交付

| 项 | 说明 |
|----|------|
| 来源分组 | 按 `note_id` 分组；组头标题/路径/片段数；组内保留扁平 `[n]` + heading |
| Snippet | 默认收起；展开后显示现有 `snippet` 文案 |
| 答案样式 | 知识库回答区补标题/列表/`code` 等间距（设计令牌） |
| 引用跳转 | Done 后将合法 `[n]` 变为可点控件；滚到对应来源行并短暂高亮 |
| 澄清条 | 识别首行 `【澄清】…`；无则用混淆对启发式兜底 |

### 1.2 不做

- 修改 `Citation` / `kb_ask` Channel 事件形状（不增加 `clarification` 字段）
- 强制模型 JSON / XML 结构化输出
- 打开笔记后滚动高亮 chunk（PRD「定位片段」另段）
- 自动改写问句并重搜
- 大面积重做顶栏 / 嵌入设置

## 2. 数据与编号

- 后端仍返回扁平 `citations: Citation[]`，`index` = 1..k，与 system 注入的 `[n]` 一致。
- **禁止**按笔记重编号；UI 分组只是展示层聚合。
- 点击组头打开笔记：`emit('open-note', note_id)`，行为与现卡片一致。

## 3. 来源列表 UI

```
来源
┌ 笔记标题                          路径 · 3 个片段 ┐  ← 点标题打开笔记
│  [1] heading…                         ▸ 摘要     │  ← 点 ▸ 或行展开 snippet
│  [5] heading…                         ▾ 摘要…    │
└──────────────────────────────────────────────────┘
```

- 组默认展开（可见全部 `[n]` 行）；**仅 snippet 默认折叠**。
- 每条片段行设 `data-cite-index="{n}"`（或等价），供跳转定位。
- 空 heading 时只显示 `[n]` + 可展开摘要。

## 4. 回答区与引用点击

1. 流式阶段：继续 `renderMarkdown(streamText)`，**不**把半截 `[` 转成按钮。
2. `Done` 后：
   - 若有澄清行，剥除后再渲染；
   - 在 HTML 中把匹配 `\[[1-9][0-9]*\]` 且 n ∈ 当前 citations 的标记替换为  
     `<button type="button" class="kb-ref" data-ref="n">[n]</button>`（实现可用 DOM 遍历或受限正则，避免破坏 code fence 内文本——**优先跳过 `pre`/`code` 节点**）。
3. 点击 `.kb-ref`：找到 `data-cite-index=n` 的来源行 → `scrollIntoView({ block: 'nearest' })` → 加高亮 class约 1.2s。
4. 答案容器补 scoped/前缀样式：`.kb-answer` 内 h1–h3、ul/ol、p、`code` 的字号与间距对齐 `DESIGN.md` / 现有正文层级。

## 5. 澄清条

### 5.1 模型协议（改 `build_rag_system_prompt`）

新增规则（大意固定，中文）：

> 若用户用词与片段主题明显不符（例如笔误、近音近形），答案**第一行**必须写成：  
> `【澄清】` + 一句说明（如「知识库内容更接近「定时器」，而不是「定位器」」），然后空一行再写正文。  
> 若无需澄清，**不要**输出 `【澄清】` 行。

### 5.2 前端解析

- 答案（或 Done 的 `answer`）按行检测：首条非空行以 `【澄清】` 开头 → 黄条文案 = 去掉前缀后的 trim；从用于 Markdown 的正文中删除该行及紧随的一个空行。
- 样式：警告/提示色用设计令牌（如偏 `--c-orange` / `--text-2`），非常驻 toast，跟本次回答走。

### 5.3 启发式兜底

- 仅当**没有**模型澄清行时启用。
- 维护小表（首批一对即可扩展）：`定位器` ↔ `定时器`。
- 条件：用户问句包含其中一侧，且任一 citation 的 `note_title` 或 `heading` 包含另一侧 → 显示较弱文案，例如：  
  `检索结果更接近「定时器」相关笔记。`
- 不修改输入框内容；不触发第二次 `kb_ask`。

## 7. 验收

1. 同一笔记多片段 → 来源区合并为一组，snippet 默认不可见，展开后可见。  
2. 答完后点正文 `[1]` → 滚到该来源行并短暂高亮。  
3. 模型输出 `【澄清】…` → 黄条出现，正文不含该行。  
4. 问「STM32 定位器…」且命中「定时器」标题、模型未出澄清行 → 仍出现兜底提示。  
5. `pre`/`code` 内的 `[1]` 不被变成按钮。

## 8. 风险

| 风险 | 缓解 |
|------|------|
| 正则替换破坏 Markdown HTML | 只处理文本节点 / 跳过 code |
| 模型乱写多行澄清 | 只认第一行非空；其余留在正文 |
| 启发式误报 | 表小、文案弱、可被模型澄清覆盖（有模型行则不用兜底） |
